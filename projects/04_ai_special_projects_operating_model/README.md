# 04 — AI Special Projects Operating Model

## Executive question

**How do you build a Special Projects function that can identify, validate, launch, and scale AI initiatives?**

The function should not become:
- an innovation theatre team
- a vendor-management office
- a central AI lab disconnected from operations
- a PMO that tracks activities without value

It should operate as a **venture-style portfolio of high-conviction initiatives**.

## Funnel

```text
Signal
  ↓
Opportunity thesis
  ↓
Use-case validation
  ↓
Data / AI feasibility
  ↓
Value case
  ↓
Pilot
  ↓
Scale / redesign / stop
```

## Required artifacts

Every initiative should have:

### Opportunity thesis
- problem
- user / operator
- why now
- AI advantage
- strategic relevance

### Technical thesis
- data sources
- model class
- architecture
- evaluation design
- integration requirements
- failure modes

### Value thesis
- baseline
- value driver
- expected impact
- cost
- sensitivity
- payback

### Operating thesis
- workflow changes
- decision rights
- adoption
- partner model
- permanent owner

## Stage gates

### Gate 1 — Discovery
Is the problem worth solving?

### Gate 2 — Feasibility
Can AI materially improve the outcome?

### Gate 3 — Pilot
Can value and technical quality be demonstrated in a controlled environment?

### Gate 4 — Scale
Are data, economics, governance, and operating ownership ready?

## Governance

Weekly product / delivery review  
Biweekly model-risk + dependency review  
Monthly investment / steering committee

## Leadership dashboard

Track:
- portfolio value at stake
- stage by initiative
- technical confidence
- value confidence
- top risks
- unresolved decisions
- time to next stage gate
- realized benefits
